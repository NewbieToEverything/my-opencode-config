# Paper Commenter

学术论文审阅与批注工具

## 输入输出规范

### 输入格式

| 类型 | 处理方式 | 工具 |
|------|----------|------|
| PDF文件 | 提取文本 | PyMuPDF (fitz) 或 pdfplumber |
| Word文件 | 读取内容 | python-docx |
| 纯文本 | 直接处理 | - |
| arXiv URL | 需先手动下载PDF再处理 | - |

**注意**: 如果是扫描版PDF（图片），需要先使用OCR处理（如pytesseract）

### 输出格式

**输出**: 单个结构化审阅报告

**可选输出格式**:
- Markdown格式: 可读性强，适合直接查看
- JSON格式: 便于程序处理和批量分析

### JSON Schema

```json
{
  "paper_title": "string",
  "total_issues": "number",
  "categories": {
    "logic": "number",
    "terminology": "number",
    "structure": "number",
    "evidence": "number",
    "cohesion": "number",
    "format": "number",
    "citation": "number",
    "language": "number",
    "methodology": "number"
  },
  "issues": [
    {
      "id": "number",
      "category": "string",
      "location": "string",
      "severity": "critical|major|minor|info",
      "issue": "string",
      "suggestion": "string",
      "example_original": "string",
      "example_suggested": "string"
    }
  ]
}
```

## 四阶段工作流程

### Phase 1: 框架分析

分析整体结构和逻辑：

1. **逻辑一致性**
   - 论点是否从引言到结论逻辑流畅？
   - 是否存在逻辑漏洞或矛盾？
   - 研究问题是否明确且被回答？

2. **术语统一性**
   - 关键术语是否全文一致？
   - 是否有模糊或未定义的术语？
   - 是否混用了相似但不同的概念？

3. **结构评估**
   - 组织是否清晰合理？
   - 各章节长度和深度是否平衡？
   - 结构是否支持论点？

### Phase 2: 分段精读

详细审阅每一部分：

1. **中心句检查**
   - 每段是否有清晰的中心句？
   - 中心句是否准确反映段落内容？
   - 段落是否统一？

2. **衔接自然性**
   - 段落和章节之间过渡是否自然？
   - 过渡词使用是否恰当？
   - 是否有突兀的话题转变？

3. **证据支持**
   - 论点是否有证据支持？
   - 证据是否适当且充分？
   - 引用是否正确？

4. **禁用词检测**
   - 标记绝对化/过于自信的语言
   - 识别模糊或含糊的表述
   - 标记非正式或口语化表达

5. **句子长度**
   - 识别过长或复杂的句子
   - 建议拆分复杂结构
   - 确保清晰可读

### Phase 3: 格式审查

验证格式标准：

1. **APA 7th格式**
   - 检查文内引用格式
   - 验证参考文献列表格式
   - 确保标题级别正确

2. **引用一致性**
   - 检查引用风格是否一致
   - 验证所有参考文献都被引用
   - 检查缺失或不完整的引用

3. **术语统一**
   - 创建术语一致性检查清单
   - 标记任何剩余不一致之处
   - 确保正确使用技术术语

4. **图表交叉验证**
   - 验证所有图表在正文中被引用
   - 检查编号一致性
   - 确保标题清晰完整

### Phase 4: 内容审读

评估论文核心内容的正确性和合理性：

1. **实验设计审查**
   - 实验设计是否真正检验了提出的假设？
   - 是否存在未控制的混杂变量？
   - 评估指标是否合理？是否存在选择性报告？
   - Baseline 对比是否公平（相同设置、相同资源）？
   - 样本量 / 统计功效是否充足？
   - 实验是否具备可复现性描述？

2. **公式推导审查**
   - 推导是否从假设到结论逻辑连贯？
   - 是否存在未声明的隐含假设？
   - 边界条件是否被考虑？
   - 变量是否都有清晰定义且全文一致？
   - 符号体系是否统一？

3. **模型 / 方法论证审查**
   - 问题建模是否正确？形式化定义是否准确？
   - 假设是否合理且在论文中被讨论？
   - 方法是否真正解决了声称的问题？
   - 是否有已知的失败模式未被讨论？
   - 与现有方法的本质区别是否说明清楚？
   - 是否存在更简单的替代方案未被排除？

4. **主张-证据一致性审查**
   - 实验数据是否真正支持结论？
   - 是否存在对结果的替代解释？
   - 结论是否过度泛化？
   - 局限性是否诚实且完整地讨论？

## 批注格式

### 注释模式

#### 完整模式
保留完整描述，用于重要问题：

```
[批注 - 逻辑]: 具体问题描述 | 修改建议 | 示例对比
```

#### 快速模式
仅简要描述，适用于次要问题：

```
[Terminology]: Use "sample size" instead of "sample number"
```

### 注释类别

| 类别 | 中文 | 使用场景 |
|------|------|----------|
| Logic | 逻辑 | 论点结构问题、逻辑漏洞 |
| Terminology | 术语 | 不一致术语、未定义概念 |
| Structure | 结构 | 组织问题、章节不平衡 |
| Evidence | 证据 | 缺乏支持的论点、弱引用 |
| Cohesion | 衔接 | 过渡问题、流畅性问题 |
| Format | 格式 | APA违规、格式错误 |
| Citation | 引用 | 引用错误、缺失参考文献 |
| Language | 语言 | 语法、风格、禁用词 |
| Methodology | 方法 | 实验设计缺陷、公式推导错误、模型不合理 |

### 注释示例

**示例1 - 术语问题:**
```
[批注 - 术语]: 术语不一致 | 全文统一使用"sample size"而非"sample number" | 建议改为："The sample size was calculated using G*Power"
```

**示例2 - 逻辑问题:**
```
[批注 - 逻辑]: 因果关系不明确 | 补充中介变量解释或修改因果表述 | 原句："X causes Y" → 建议："X is associated with Y through Z"
```

**示例3 - 证据问题:**
```
[批注 - 证据]: 缺乏实证支持 | 添加相关研究引用或删除此论断 | 建议引用：(Smith, 2020; Johnson, 2021)
```

**示例4 - 禁用词:**
```
[批注 - 语言]: 使用绝对化词汇"prove" | 学术写作应避免绝对化表述 | 原句："This proves that..." → 建议："This suggests that..." 或 "These findings indicate that..."
```

**示例5 - 方法问题:**
```
[批注 - 方法]: 实验设计存在混杂变量 | 控制XX因素或使用XX方法排除 | 建议增加A/B组的同质性检验
```

## 禁用词列表

标记以下类型的词语和短语：

### 绝对化 / 过于自信
- prove, proves, proven
- always, never
- definitely, certainly, absolutely
- without doubt, no doubt
- conclusively, definitively
- all, every, none

### 模糊 / 不明确
- very, quite, really, pretty
- somewhat, somehow
- things, stuff
- etc. (when overused)
- several, many, some (without specificity)

### 非正式 / 口语化
- get, got
- a lot, lots of
- kind of, sort of
- big, small (use specific measurements)
- good, bad (use specific evaluative terms)

### 不必要的模糊
- maybe, perhaps (in strong contexts)
- might, could (when certainty is appropriate)
- probably (without statistical basis)

## 科学写作原则

应用以下四项原则：

### 1. 清晰性
- 使用精确语言
- 定义技术术语
- 尽量避免行话
- 确保每句一个观点

### 2. 简洁性
- 删除冗余词语
- 消除冗长
- 适当使用主动语态
- 避免不必要的修饰词

### 3. 准确性
- 使用精确术语
- 确保事实正确
- 提供具体细节
- 避免过度概括

### 4. 客观性
- 中立地呈现证据
- 承认局限性
- 避免情绪化语言
- 区分事实和解释

## 学科特定指南

### 计算机科学
- 算法复杂度描述是否准确
- 实验设置是否可复现
- 代码/伪代码格式是否规范
- 是否正确引用开源项目

### 生物 / 医学
- 统计方法是否正确
- 样本量计算是否有依据
- 是否有伦理审批声明
- 临床试验注册号是否提供

### 社会科学
- 问卷/量表是否有信效度报告
- 抽样方法是否合理
- 人口学特征是否描述完整
- 是否有方法论局限性讨论

### 工程
- 实验参数是否完整描述
- 是否与现有方法进行对比
- 是否有消融实验
- 是否讨论了实际应用场景

## 有效批注的建议

1. **具体明确**: 指向具体的句子或短语
2. **提供替代方案**: 尽可能提出更好的措辞
3. **解释原因**: 简要说明建议背后的原则
4. **分清主次**: 先关注核心内容问题，再处理次要风格问题
5. **平衡批评**: 适当承认优点
6. **区分层次**: 内容正确性优先于语言风格

- 是否批判性评估了纳入研究？

## 输出报告结构

最终审阅报告按以下结构组织：

### 总体评价（2-3 句话）
概括主要发现和整体判断，包括论文的优势和核心待改进点。

### 主要问题
必须由作者解决的严重问题，按严重度降序排列。

每条包含：
```
[CRITICAL/MAJOR] [类别] 问题描述
- **原因**: 问题产生的根因
- **建议**: 具体的修改建议
- **位置**: 涉及的章节或段落
```

### 次要问题
建议修改但不影响主要结论的问题，同样按严重度排序。

每条包含：
```
[MINOR/INFO] [类别] 问题描述
- **建议**: 修改建议
- **位置**: 涉及的章节或段落
```

### 行级批注（可选）
逐句或逐段的批注，适用于语言润色、术语统一等细节问题。

格式：
```
[行号/位置] [类别] 问题 → 建议
```

### 给作者的问题
需要作者澄清的疑问，不直接评判，而是引导作者思考。

每条包含：
```
[Q1] 问题描述（涉及的具体位置）
```

### 统计摘要
```
- 总计: XX 条
- 按严重度: CRITICAL X / MAJOR X / MINOR X / INFO X
- 按类别: logic X / methodology X / language X / ...
```

### 完整示例

```
# 审阅报告：XXX

## 总体评价
本文在XX方面有创新性，但在实验设计和方法论证上存在若干问题。

## 主要问题

[CRITICAL] [方法] 实验设计存在混杂变量
- 原因: 实验组和对照组在XX变量上系统不同
- 建议: 使用协变量分析控制XX因素
- 位置: Methods 2.3节

[MAJOR] [方法] 样本量不足
- 原因: 仅N=10，未做power analysis
- 建议: 补充power analysis或讨论统计功效限制
- 位置: Methods 2.1节

## 次要问题

[MINOR] [术语] "sample number" 与 "sample size" 混用
- 建议: 全文统一使用 "sample size"
- 位置: 多处

## 给作者的问题

[Q1] 数据收集分3个批次进行，是否存在批次效应？(Methods 2.1节)
[Q2] 为什么选择A方法而非B方法？是否有对比实验？(Methods 2.3节)

## 统计摘要
- 总计: 18 条
- 按严重度: CRITICAL 2 / MAJOR 4 / MINOR 8 / INFO 4
- 按类别: logic 3 / methodology 7 / language 4 / format 2 / citation 1 / evidence 1
```
